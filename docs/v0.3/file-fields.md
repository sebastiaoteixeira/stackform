---
title: File fields
description: The `file` field type, arrays of files, the metadata stored in records, and how size and type limits are resolved.
---

A field with `type: file` holds an uploaded file. The bytes go to the entity's
[file datastore](file-datastores.md); the record keeps only the file's metadata.
File fields are v0.3 behavior.

```yaml
api:
  files:
    maxSize: 10MB
    types: [image/*, application/pdf]
    maxFiles: 10

entities:
  post:
    fields:
      id: { type: id }
      title: { type: string, required: true }
      cover:
        type: file
        required: true
        maxSize: 2MB
        types: [image/png, image/jpeg]
        disposition: inline
      attachments:
        type: array
        maxItems: 5
        items: { type: file, types: [application/pdf] }
```

## Options

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `required` | boolean | `false` | A create must upload the file, and it cannot be removed. |
| `readonly` | boolean | `false` | Clients cannot upload it (`422`), and no replace or remove endpoint is derived for it. It can still be downloaded. |
| `maxSize` | size | inherited | Largest accepted upload (see [Sizes](#sizes)). |
| `types` | list of MIME types | inherited | Accepted content types. `image/*` matches every image subtype. |
| `disposition` | `attachment` \| `inline` | `attachment` | How browsers are told to handle the download. |

`unique`, `default`, `min`, `max`, `minLength`, `maxLength` and `format` do not
apply to files and are rejected with `FIELD_CONSTRAINT_INVALID`. So are
`maxSize`, `types` and `disposition` on a non-file field.

### Arrays of files

`type: array` with `items: { type: file, ... }` holds several files. The item
options (`maxSize`, `types`, `disposition`) apply to each file. `maxItems` on
the array caps how many files it holds; `maxItems` on any other field is
rejected.

### Where file fields are allowed

File fields are top-level entity fields or top-level arrays of files. They are
rejected:

- inside `type: object` properties, in arrays of arrays, or deeper
  (`FILE_FIELD_NESTED`);
- in `dto:` fields and service `input:` fields (`FILE_FIELD_CONTEXT_INVALID`);
- in `where`/`when` comparisons and pagination sort keys
  (`FILE_FIELD_NOT_COMPARABLE`).

## Stored value

A record holds, for each file, this metadata object (a list of them for an
array, `null` when an optional file is absent):

```json
{
  "id": "0192f3c4-8d1e-7b3a-9c2f-5e6a7b8c9d0e",
  "name": "report.pdf",
  "size": 48213,
  "contentType": "application/pdf",
  "sha256": "9f2c...e1",
  "store": "disk",
  "uploadedAt": "2026-10-01T09:30:00+00:00"
}
```

- `id` is generated by the server; clients never choose it.
- `name` is the client's filename reduced to its last path segment, with
  control characters removed and at most 255 characters (`file` when nothing is
  left).
- `contentType` is the type detected from the content, not the one the client
  sent.

PostgreSQL stores the value in a JSON column; MongoDB stores it as a
subdocument. Record responses return it as is.

## Limits and precedence

Each limit is resolved per field, from the most specific level that sets it:

| Limit | 1. Field | 2. File datastore | 3. `api.files` | 4. Built-in |
| --- | --- | --- | --- | --- |
| Size | `maxSize` | `files.maxSize` | `maxSize` | 10MB |
| Types | `types` | `files.types` | `types` | any type |
| Files in an array | `maxItems` | | `maxFiles` | 10 |

A level replaces the levels below it; they are not combined. A field with
`types: [application/pdf]` accepts PDFs even if `api.files.types` only lists
images.

```yaml
api:
  files: { maxSize: 3KB }            # 3. assets' blob: 3KB
datastores:
  disk:
    type: filesystem
    path: ./uploads
    files: { maxSize: 2KB }          # 2. documents' scan: 2KB
entities:
  document:
    fields:
      cover: { type: file, maxSize: 1KB }   # 1. 1KB
      scan: { type: file }
```

### Sizes

`maxSize` is a positive byte count (`1048576`) or a number with a unit: `B`,
`KB`, `MB` or `GB`. Units are **binary** and case-insensitive: `1KB` is 1024
bytes, `1MB` is 1024² bytes and `1GB` is 1024³ bytes. Decimals are allowed and
rounded down (`1.5KB` is 1536 bytes). Anything else is `FILE_SIZE_INVALID`.

### How uploads are checked

- **Size** is counted while the upload streams. The request fails with
  `413` as soon as it passes the limit; the server never buffers the whole file.
- **Type** is detected from the first bytes of the content. A PDF sent as
  `image/png` is a PDF. A disallowed type fails with `415` before anything is
  stored. When the content has no recognisable signature, UTF-8 text keeps its
  declared textual type (`text/*`, `application/json`, `application/xml`,
  `*+json`, `*+xml`) or becomes `text/plain`; other content becomes
  `application/octet-stream`.

## Disposition

`disposition: inline` lets browsers display the file, but only for safe types:
images other than SVG, `application/pdf`, audio, video and `text/plain`. Every
other type, and every file of an `attachment` field, is downloaded as an
attachment.
